## 在本机重建 PNG

依赖 Java；本次环境检测为 Java 17。渲染器固定 PlantUML 1.2025.10，不依赖在线渲染服务。结构图使用内置 Smetana 布局，不另装 Graphviz。中文字体设为 Windows 的 Microsoft YaHei；换机器需有该字体或修改源码字体设置。

从仓库根目录运行：

```powershell
# 已有 JAR 时完全离线运行
powershell -NoProfile -ExecutionPolicy Bypass -File .\phase2\render-uml.ps1

# 首次拉取仓库，没有 JAR 时：下载固定版本并生成
powershell -NoProfile -ExecutionPolicy Bypass -File .\phase2\render-uml.ps1 -Download

# 也可指定自己已有的 PlantUML JAR
powershell -NoProfile -ExecutionPolicy Bypass -File .\phase2\render-uml.ps1 -PlantUmlJar 'C:\tools\plantuml.jar'
```

脚本对每份源文件调用本地 Java 渲染，成功后更新同目录 PNG；检查退出码和 PNG 签名、记录尺寸与源文件 SHA-256 至 `uml-build.json`。失败时保留临时诊断，避免错误图片覆盖已有有效成果。图片使用 140 或 160 DPI，不缩放为聊天预览尺寸；源码可继续编辑。

JAR 存在 `tools/` 并由 `.gitignore` 排除。依赖只需首次下载；提交实验时复制 `UML/` 即可，不必附上约 25 MB 的渲染器。

工具依据：[PlantUML 官方命令行文档](https://plantuml.com/zh/command-line)。

## 本次采用的实现设计选择

这些是从需求落实的设计方案，不能当作实验一新增的甲方确认：

- 模块化单体与本地 SQLite；业务写事务用 `BEGIN IMMEDIATE` 串行化资格、排期、库存及状态检查，配合唯一约束。正式实现仍须验证事务长度、锁等待与查询性能。
- 账号使用固定 `role` 字段；用例图角色互不继承。类图仅描述领域关联，不要求“一类一表”。
- 候补直接使用报名单的候补状态；当前检票授权与不可回改的历史签到分开存储。
- 每次支付或退款尝试保留结果；退款资格单独持久化，管理员重试有依据的失败申请。订单的“每单最多一次成功退款”不妨碍保存失败尝试。
- 核心数据与治理数据分图展示；字段和方法是代表性设计接口，详细数据库列与接口定义留待后续实现。
- 业务、成功日志和必发消息在同一数据库事务内提交，不把站内消息交给不可保证原子性的外部消息服务。
- 任务待办及终止时事实持久化，单项事务推进；事务释放后由任务继续处理，不把全活动结算放进一个长事务。
