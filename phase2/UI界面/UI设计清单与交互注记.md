# UI 设计清单与交互注记

此文件是设计交付索引与控件注记，不是实验报告正文。报告中的功能描述、设计理由、AI使用分析与反思请本人撰写。

依据 `phase2_req.md`：为每个功能模块设计 UI，附必要文字说明；工具举例为“亿图图示等绘制工具”，未指定唯一产品；提交 UI PNG。本次使用 Figma 创建可编辑画板，沿用已确认莫兰迪风格。

已确认主流程：04 本人报名 → 有票成功创建未支付订单后立即进入05 → 用户点击模拟支付 → 06 电子票。需要排队时进入08；后端业务失败时应停留并提示原因，不能伪造成功跳转。原型连接展示的是正常成功路径。

## 视觉规范

背景 `#F6F4F0`，面板 `#FFFEFC`，主色灰玫瑰 `#A97773`，辅助鼠尾草绿 `#7C8C7C`，正文 `#303632`，边框 `#DFDED8`。色块低饱和，正文保留足够深度。桌面画板宽1440，长页完整导出而非裁掉内容。Figma 正文为 Noto Sans SC，标题为 Noto Serif SC；本地渲染在缺少这两种字体时采用 Windows 中文字体回退。

## 文件范围与演示数据

28 张带编号 PNG 为本次模块界面；`00-界面总览.png` 和 `界面索引.html` 为浏览辅助。`01-购票页面-风格预览-v1.png` 是先前确认风格时的 imagegen 参考，保留原文件，不作为新的本人报名页；新页为04。示例名称、手机号、票id、价格、时间、人数均为演示数据；不同模块中的统计/状态示例不是同一时点的完整业务数据库。

本次交付是界面设计及部分原型导航，不实现账号鉴权、库存事务、真实倒计时或支付。名单、消息、资料等共用组件的角色变体在上表注明；管理员、组织者与检票员不可在真实系统中切换成参与者身份访问私人数据。
