# 活动票务 · 桌面网页前端

Vue 3 + TypeScript + Vite + Vue Router + Pinia。沿用phase2确认的莫兰迪配色、中文衬线标题、插画海报、米白面板和工作台侧栏。

**当前本机已切换HTTP，连接Java/MySQL/Redis，后台任务已启用。** 真实演示账号为`participant_demo / organizer_demo / checker_live_demo`，密码`DemoPass123`；管理员`admin_demo`初始密码`AdminDemo123`，首次必须改密。运行方法、全部账号、活动及联调记录见[HTTP演示说明](../../docs/http-demo.md)。须同时启动Java后端；下方mock账号和重置方式仅适用于显式mock模式。

**目标是Windows桌面浏览器网页，不是手机应用。**建议使用Edge或Chrome，窗口宽度1280px以上、缩放100%；页面最小布局宽度1180px。Codex旁侧预览窗太窄时会出现横向滚动，可在独立浏览器窗口打开查看。

## 运行查看

需要Node.js 22.12以上（本次构建环境为Node 24.14）。在VS Code打开仓库，选择“终端 → 新建终端”，运行：

```powershell
cd D:\2026Fall-SE\phase3\code\frontend
npm.cmd ci
npm.cmd run dev
```

浏览器访问 **http://127.0.0.1:5173/**。保留终端运行；停止时按Ctrl+C。使用`.cmd`写法可避免部分Windows PowerShell环境的npm.ps1执行策略限制。

本机已安装过依赖且package-lock.json未变化时，可以直接`npm.cmd run dev`。若5173端口被占用，先停止旧开发终端，或使用：

```powershell
npm.cmd run dev -- --port 5174
```

然后打开终端实际显示的网址。不要直接双击index.html；Vue源码需要Vite处理。

## 可选mock模式的阅览路径

1. 访客打开“发现活动”：分类、关键词、地点/价格/票种/状态、日期和排序，查看活动详情。
2. 用participant登录，打开“晚风来信”：确认报名 → 确认模拟支付 → 电子票 → 下载UTF-8文本票；从订单详情申请全额模拟退款。
3. “我的订单”中有已报名及候补示例，可看候补状态；候补通知、消息已读、举报提交及本人进度均有页面。
4. 退出，换organizer登录：新建活动、添加场次票种、保存不完整草稿、提交/撤回审核；已发布活动可编辑允许字段，并查看名单/CSV/实时计数。
5. 换admin登录：审核待办、先配置场次检票员再审核；类别增改启停、举报核查、交易记录和单条审计；终止操作会在模拟层生成任务记录。
6. 现场验票：先用participant在“我的订单”找到“现场核验 · 校园午后专场”的电子票并复制票号；退出后用checker登录，粘贴票号 → 核对 → 确认签到。该独立夹具从初始化所在整点开始，持续2小时；其他未来活动票会被正确拒绝为跨场或窗口未开放。

演示日期相对首次初始化时刻生成。若时间已过、想恢复初始活动或撤销本地演示操作：登录任一演示账号，打开右上角“账号与安全 → 重置本地演示”，确认后恢复四账号及示例并退出。每个浏览器/来源地址各有自己的演示数据；localhost与127.0.0.1不共享存储。

## 当前实现范围与边界

- 前端路由、桌面布局、表单、模态框、状态反馈、角色导航、数据列表与详情已实现；路由守卫包含登录、固定角色和强制改密。
- 所有页面通过`src/api/client.ts`调用接口，模拟数据统一在`src/mocks/`，没有把假成功跳转散落在页面中。未设置VITE_API_MODE时使用mock，不需要Java；本机.env.local已设为http。
- 本地模拟覆盖主要阅览流程，并提供登录/对象范围、重复请求、截止、库存、支付出票、退款、检票和部分管理行为。模拟层用浏览器localStorage保存演示状态、sessionStorage保存会话；**它不是Java后端，也不是安全认证或数据库实现**。
- mock中的注册/改密为浏览器本地演示，密码会出现在本机数据中，只使用演示信息。当前HTTP注册/改密交由Java，密码以哈希持久化；真实并发、灾难恢复、性能及全部7/180天边界仍需后续验收。
- 支付/退款仅模拟，不连接资金平台；票据是文本，不含二维码。模拟终止结算同步完成并明确标记，不代表已经验证正式后台5分钟恢复目标。
- 业务限制页当前没有达到处罚阈值的夹具，因此显示真实空状态，保留未来候选核实入口；失败退款重试入口只在有FAILED合法依据时显示，正常页面不暴露失败注入开关。
- 海报可选本机JPEG/PNG并保存本地演示，大小受5,000,000字节上限及浏览器存储配额约束；正式文件校验/受控存储仍由Java接管。

## HTTP与mock模式切换

复制`.env.example`为`.env.local`，设置：

```dotenv
VITE_API_MODE=http
VITE_DEMO_ACCOUNTS=true
```

本机已完成上述设置并重载Vite。`/api`代理到`http://127.0.0.1:8080`，路径保持不变。http模式不回退模拟数据；后端未启动时显示请求失败。HTTP模式不提供“重置本地演示”，旧浏览器数据不迁入MySQL。若需要单独阅览旧mock，将VITE_API_MODE改为mock并重启Vite；不要把mock结果当作后端验收。正式部署关闭VITE_DEMO_ACCOUNTS，按[接口文档](../../docs/api.md)继续核对剩余分支。

## 构建与检查

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build`先运行严格TypeScript/Vue检查，再生成`dist/`。preview默认地址以终端输出为准（通常http://127.0.0.1:4173）。`dist/`供后续Java静态资源打包使用，不直接双击打开。源码、锁文件和说明纳入Git；`node_modules/`、`dist/`和本地环境文件已忽略。

`npm.cmd run format`整理源码，`npm.cmd run format:check`检查格式。页面与验证记录见[前端交付清单](../../docs/frontend-delivery.md)。
