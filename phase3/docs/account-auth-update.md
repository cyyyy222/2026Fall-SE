# 账号、手机号登录与管理员工作空间调整

日期：2026-11-03。以下为用户最新确认，优先于phase1历史文件中的旧口径；原phase1/phase2材料保留，不回改历史实验材料。

## 账号规则

| 类型 | 创建方式 | 手机号 | 登录方式 |
| --- | --- | --- | --- |
| 参与者 | 用户注册 | 必填，同角色有效账号内唯一 | 用户名密码或手机号验证码 |
| 组织者 | 用户注册 | 必填，可与参与者共用手机号，同角色内唯一 | 用户名密码或手机号验证码 |
| 管理员 | 首个由系统初始化；保留已有管理员创建其他管理员的能力 | 无需填写 | 用户名密码；新管理员首次必须改密 |
| 检票员 | 管理员创建，选择活动及具体场次 | 无需填写 | 用户名密码，只能检查授权场次 |

一个账号角色固定。组织者拿到检票账号后，需要退出组织者账号，再使用检票账号登录；这不会把组织者账号升级为检票员。每场至少一名、可配多名，一个检票账号当前只绑定一场；多名同时值守使用不同账号，避免单账号唯一会话互相撤销。改绑可选择其他活动的待审/已发布未结束场次，末位保护与活动结束失效规则保留。

用户名、邮箱仍全局唯一，本次只放宽不同普通角色之间的手机号复用。同一个真实手机号仍只对应一条phone_identities历史身份，两个角色的账号指向这条身份；报名限制REGISTER只作用参与者，发布限制PUBLISH只作用组织者，展示和通知也按类型隔离。未改动原手机号级注销次数、365天间隔与黑名单规则，它们仍按手机号身份累计；没有借本次改动清除历史处罚。

## 验证码登录和注册

1. 登录页提供“账号密码登录 / 手机号验证码登录”。手机号方式先选参与者或组织者，再填手机号并获取验证码。
2. 注册页仍填写用户名、密码、邮箱及角色，同时必须验证手机号。不能跳过验证码调用注册接口。
3. 本机六位验证码由Java服务端SecureRandom产生，5分钟有效，发送同手机同角色后60秒内不重复发送，登录与注册共用发送冷却。一次挑战最多5次错误，成功登录/注册后立即消耗；重新发送替换同用途旧挑战。
4. Redis保存HMAC码摘要和随机挑战ID，不保存原始码或原始手机号key；用途LOGIN/REGISTER和角色绑定，不能拿参与者验证码登录组织者。Redis不可用则明确失败，不绕过验证。
5. 注册时验证成功后，若同角色已有账号，返回409 PHONE_ACCOUNT_EXISTS，前端弹出“这是你的账号吗”。选择“这是我的账号，直接登录”复用这次REGISTER挑战登录原账号并消耗验证码；选择“不是我的”不覆盖、不删除原账号，联系平台核实。未验证手机号前不公开查询其账号是否存在。
6. 尚未注册的手机号不能自动生成账号；验证后提示先注册。管理员/检票角色不接入手机号登录。

发送接口`POST /api/auth/phone-codes`，手机号登录`POST /api/auth/phone-login`。注册新增verificationId、verificationCode必填；详细请求/响应以[api.md](api.md)为准。旧账密登录及7天固定单会话规则保持，新增路由后业务接口共91项。

## 本地查看验证码

验证码只在app.environment=local时允许通过日志交付；非local环境会拒绝，未接真实短信供应商。网页只显示挑战编号和有效期，不返回验证码。

在启动Java后端的终端查找：

```text
[LOCAL_PHONE_CODE] phone=所填手机号 role=PARTICIPANT或ORGANIZER purpose=LOGIN或REGISTER code=六位验证码 validSeconds=300
```

当前本机后端启动附带`--logging.file.name=backend-local.log`，仍输出终端，并保存一份被Git忽略的开发日志。也可以在VS Code另一个PowerShell终端查看：

```powershell
cd D:\2026Fall-SE\phase3\code\backend
Get-Content .\backend-local.log -Tail 20 -Wait
```

这仅用于本地联调。后续在自己的终端前台启动Java，也可直接看该终端输出；新获取的验证码以最近一条同手机号、同角色、同用途日志为准。真实部署必须接短信交付服务，不能把本地日志视为实际短信收件验证。

## 管理员页面

账号模块按服务端role过滤与分页拆为四类：参与者账号、组织者账号、检票账号与授权、管理员账号。普通账号只查看，不在此切换身份或直接绕过找回依据重置。手机号只展示脱敏值；管理员和检票员显示“无需绑定”。创建按钮只出现在管理员及检票员模块。

创建检票账号时先选活动，再选该活动内未结束的场次。成功后展示一次账号、初始密码、活动场次及登录地址，可复制交接信息；管理员自行交给活动组织者安排工作人员。系统不自动发送外部消息，不存可回查明文密码；页面刷新或关闭凭据卡后不再显示，遗失时重置。重置密码成功后同样只展示一次新临时密码，便于重新交接。

| 原名称 | 新页面名称 | 实际作用 |
| --- | --- | --- |
| 人工找回 | 账号找回申请 | 用户在忘记密码提交用户名和登记手机号；工作人员通过当面或已有联系渠道核实本人，记录依据后重置临时密码并自行告知本人 |
| 持久任务 | 后台处理进度 | 查看超时取消、候补递补、退款/结算等自动任务进度；记录在数据库，可恢复执行，管理员不用逐单操作 |
| 操作审计 | 操作记录 | 查询谁在何时对哪个账号/活动/订单执行了什么，成功或失败，便于追溯；不是修改业务数据的入口 |
| 业务限制 | 报名与发布限制 | 根据合格缺席、主动退款或组织者违规事实限制新的报名/发布，不影响合法已有订单履约 |

“线下核验”不代表必须去某个办公室，也不是已经接入电话、短信或聊天系统。当前系统只收取表单并保存管理员核验记录，核验过程由工作人员在系统外完成。人工找回仍保留给不能通过现有凭据处理的情况；手机号登录本身不提供“免原密码修改密码”接口。
