## 1. 入口与运行

源码目录：[code/frontend](../code/frontend/README.md)。建议先阅读该目录的运行说明和演示账号。

```powershell
cd D:\2026Fall-SE\phase3\code\frontend
npm.cmd ci
npm.cmd run dev
```

打开 **http://127.0.0.1:5173/**，使用Edge/Chrome桌面窗口，建议1280px以上。关闭开发终端会停止服务；端口冲突时可用`npm.cmd run dev -- --port 5174`，以终端显示地址为准。

默认mock模式不需要Java或数据库。四个演示账号participant / organizer / checker / admin，密码均为Demo2026。切换身份须退出后重新登录；不是一个账号多角色切换。

## 3. 代码组织与后端衔接

- `src/views/`：各角色页面；`src/components/`：导航所用图标、海报、状态标签、弹窗、空态和页标题。
- `src/router/`：hash路由及登录/角色/强改密守卫；`src/stores/`：Pinia用户和提示状态。
- `src/api/client.ts`：mock/http切换、统一错误、Cookie/CSRF、请求键、下载和海报上传。
- `src/types/`：共享TypeScript模型；`src/utils/clock.ts`：依据serverTime校准支付倒计时。
- `src/mocks/`：本地夹具和模拟适配器；不会生成真正的Java服务、数据库或安全边界。
- `tests/mock-flows.test.ts`：用隔离内存存储检查模拟数据流，测试不会修改浏览器实际演示数据。

工程初始化时的依赖精确版本保存在package-lock.json；本次Node为24.14、npm为11.9，实际Vite解析版本为7.3.7。后续接入设置`VITE_API_MODE=http`，代理`/api`至Java 8080，须按api.md逐项联调。前端已消费接口不代表89个HTTP接口均已正式实现。

## 4. 本轮验证

### 4.1 自动检查

已执行并通过：

- `npm.cmd test`：6项模拟层流程测试。涵盖匿名/私有读取、报名支付出票退款、重复请求异参/角色权限、检票唯一性、草稿与审核退回、CSV BOM及末位检票员保护。
- `npm.cmd run build`：严格`vue-tsc --noEmit`类型检查与Vite生产构建，产物为`dist/`。
- `npm.cmd run format:check`：Vue、TypeScript、CSS和配置的统一格式检查。

这些测试仅验证本前端及模拟层，不代表后端事务/安全/性能验收完成。

### 4.2 浏览器实际操作

在Codex内置浏览器中检查桌面页面；按用户桌面要求使用1440×1000检查布局，不将其写成已验证Edge版本。

1. 访客活动详情 → 登录participant返回原活动 → 确认报名 → 确认模拟支付 → 电子票。
2. 实际下载文本票据 → 订单全额模拟退款 → 订单显示退款记录。
3. organizer工作台与发布后编辑表单；新建草稿 → 添加场次/票种 → 保存并确认成功提示。
4. admin审核工作台、类别新增及表格刷新。
5. 从participant的现场演示票取得票号 → checker登录 → 核对 → 确认签到，看到首次签到时间。
6. 修复首屏活动先于分类加载导致的负数海报索引渲染错误；之后上述检查未发现新的Vue运行时错误。
