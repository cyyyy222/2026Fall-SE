# 需求响应路径与验收追踪

版本：v0.2（需求与冲突复核后，待审阅） · 日期：2026-11-02。

本表逐条覆盖 [phase1 version5 的 REQ-001～REQ-053](../../phase1/my_exp_cont/requirements.md)，正文及附录 A～D 一并有效。表中“响应路径”指**页面入口 → API → 后端用例 → 数据/任务 → 用户可观察结果**，包括正常、异常与异步路径；不只表示一个URL。API编号定义见 [api.md](api.md)，页面与模块定义见 [project.md](project.md)。

状态统一为“已规划、未实现、未验收”；下面的验收列是未来检查目标，不是通过记录。JOB-*为内部用例，不是外部接口；跨所有接口的约束不能仅通过某一页面验收。

## 2. 跨模块用例的实际响应路径

### FLOW-01 正常购票

`/events` PUB-02 → `/events/:id` PUB-03 → ME-06 → order/register（权限、时限、唯一、冲突、队列、库存）→ order+占位+audit提交 → `/orders/:id/pay` → ME-13 → payment/confirm（原尝试、最新事实）→ payment+ticket+REGISTERED+audit+message提交 → `/tickets/:id` ME-19。

失败分流：资格/时间错误留在原页并显示code；候补转waitlist；网络未知保留原requestId/attemptId，通过ME-09或ME-08/14恢复。不能依据本地mock或按钮点击跳成功页。

### FLOW-02 候补递补

ME-06返回WAITLISTED → ME-11本人位次 → 释放/新增名额触发JOB-02 → 合格队首OFFERED+占位+通知同事务 → ME-24 → ME-12确认 → UNPAID且保留原占位 → ME-13支付出票。拒绝/超时→取消释放→下一位；停售/锁定/终止分别按基线暂停、跳过或终止，不延长报名截止。

### FLOW-03 审核与发布

ORG-02/04草稿 → ORG-07完整性+时间+排期校验 → PENDING_REVIEW → ADM-02配置每场检票员 → ADM-10发布复核 → 成功则PUBLISHED+每日额度+日志消息同事务；当前条件无效则200 RETURNED_TO_DRAFT+原因，前端显示“已退回修改”。撤回/驳回竞争通过当前状态和version只允许一个生效。

### FLOW-04 主动退款与故障恢复

订单详情显式确认 → ME-15 → T1保存合法依据 → T2成功退款/失效票/释放/REFUNDED/日志消息 → 结果展示。T2失败业务回滚，依据保留：ME-16查状态 → ME-17本人重试或ADM-18管理员按失败依据重试。当前已签到/终态必须拒绝，不能依旧申请无限放宽条件；同attempt响应未知重放原键。

### FLOW-05 验票与取消竞争

CHK-01授权上下文 → CHK-02先鉴权核对 → CHK-03重新鉴权、读最新事实、原子唯一签到。ORG-10并发时，签到先提交则组织者取消拒绝；取消先提交则新签到拒绝。管理员据证下架可在有签到时生效，保留签到完成，不退已签到票。

### FLOW-06 下架、持久结算与报表

ADM-20属实证据 → 同事务记录事实/组织者违规/举报结论/下架时刻/原事实待办 → 立即拒绝交易验票 → JOB-04逐单取消或退款/完成+日志消息+进度 → 所有项完成后生成正式快照 → MGT-06可读。处理中显示PROCESSING，重启从原待办恢复，5分钟目标超时仍继续但标未达标。

### FLOW-07 期限与历史

自然终结最晚场次结束/取消下架生效 → 计算+7天统一expiresAt → MGT名单、CSV生成/下载、报表到点410，不依赖JOB-05先清理。ME-07/19本人底层历史继续可读，ADM-25只允许单条对象链；不能从这些接口批量重建过期活动名单。日志180天物删、消息180天逻删独立执行。
